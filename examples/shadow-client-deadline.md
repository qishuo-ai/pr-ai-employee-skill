# Example: Client asks for an unrealistic weekend deadline

## Input
A client asks on Friday whether the full deployment can be completed over the weekend. Required domain-specific training is not yet complete.

## Judgment
- task: client_reply / project_ops
- underlying need: speed + certainty
- risk: RED because the reply can create a delivery commitment
- key issue: agreeing immediately may create an unachievable promise and reduce final quality
- action: explain the necessary preparation, provide only a verified delivery window, require human approval

## Example draft
> We won't be able to complete the full deployment over the weekend. There is still domain-specific training and adaptation required, and we'd prefer to finish that properly so the system performs reliably in actual use. Based on the current plan, the earliest realistic window is early next week; I'll confirm the exact timing with the delivery team before we lock it with you.

The important behavior is not the wording. It is recognizing that this is a **delivery commitment**, not a generic customer-service question.

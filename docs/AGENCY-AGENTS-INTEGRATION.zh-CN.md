筛选标准是能否补足现有公关员工的实际交付：客户需求 → 研究与策略 → 内容与渠道 → 创意制作 → 商务与执行 → 审核与复盘。保留五个核心岗位的责任，避免多个同义管理岗争夺决策权。

## 整合后的岗位

共25张岗位卡：原有5个核心岗位细化，新增20个按需专才。完整名单仅维护在 [岗位目录](../roles/README.md)，任务配方见 [团队路由](../playbooks/team-routing.md)。

| 来源能力 | 本地落点 | 具体可用产出 |
|---|---|---|
| CMO、PR经理、内容创作、编排、项目管理、证据审核 | 原有五个核心岗位 | 分账衡量、故事pitch、母稿复用、依赖交接、纪要与审核证据 |
| 趋势/反馈研究、PR传播、平台策略 | 研究洞察、媒体KOL、社媒统筹 | 证据卡、机会判断、候选任务匹配、内容矩阵 |
| 小红书、抖音、微信、微博、B站 | 五类中国平台岗位 | 平台内容草稿、选题/脚本、创作者brief与复盘 |
| 海外平台、本地化、AI搜索可见性 | 海外社媒、GEO | 市场表达适配、查询样本、引用证据与测量 |
| 品牌、视觉叙事、图像/视频提示词 | 品牌守护、视觉叙事、图像导演、视频导演 | 品牌一致性检查、逐页计划、视觉brief与分镜提示词 |
| 分析/实验、提案/预算、工作流架构 | 数据分析、商务提案、AI工作流 | 指标定义、实验复盘、范围测算、功能/数据/权限/试点设计 |
| 危机、用户生命周期、社交广告 | 危机研判、私域车主、付费传播 | 事实控制、社群服务SOP、线索承接、付费测试方案 |

合并同类来源：如小红书两份岗位、微信多种运营岗位按任务汇总；没有照搬全部岗位或为每个上游文件创建一位员工。工程、游戏、交易、医疗等不服务当前公关职责的角色不进入默认团队；AI系统岗只吸收业务工作流方法，不自动引入开发与部署工具。

## 冲突与改写

| 上游发现 | 本地处理 |
|---|---|
| 部分角色拥有虚构过往战绩、永久记忆或“已操盘”人设 | 改成可检验职责，不宣称真实任职、客户关系或持久记忆 |
| 危机岗位主张抢先发布、固定时间内先发再完善 | 继承事实门、统一口径、授权发言与审批要求，先完成内部草稿 |
| 多平台发布角色声称草稿优先，却出现 `publish` / `upload` 命令 | 仅吸收分平台内容适配；不导入命令、账号凭据或隐含授权 |
| 图片MD5变化、随机发布间隔等规避机制 | 不采用；内容原创性、权利与平台规则正常核对 |
| 固定互动率、ROI、打开率、平台权重或最佳时段，且来源之间有差异 | 改为有日期、来源、样本、口径的基线与待验证假设，不承诺效果 |
| 自动编排直至“生产就绪”、无限延伸任务或假完成状态 | 按需求范围、证据、独立审核及真实回执推进；无新输入的阻塞如实记录 |
| 工程路径、工具安装、MCP、广告账户、外发与部署权限 | 不引入依赖，也不修改现有授权边界 |
| 单个角色全权生成与验收 | 初稿作者与独立审核分离；单会话换角色仅属自检 |

这些处理是对所选方法的适配，不代表对上游全部代码的安全审计或所有平台规则的认证。

## 与原仓库的兼容

- 原有风险政策、汽车事实政策、业务playbook与E01–E10保持；Shadow Mode不变。
- 五个原岗位继续担任统一入口、策略、口径、交付与独立审核。
- SKILL入口仅增加渐进加载与路由规则，详细方法在岗位卡中。
- `roles/registry.json` 是声明式索引，不是能自动启动25名Agent的程序。
- 本次未增加工具凭据、外部服务、MCP、平台自动发布或后台监测。
- `display_name/version/language/default_mode` 迁入 frontmatter 的 `metadata`，保留技能ID `pr-ai-employee`。旧自定义读取器若读取顶层字段需要相应调整。
- 公开仓库不包含私人项目记忆、客户Brief、内部报价、联系人、聊天记录或私有版式。

## 验证与使用

结构检查（Python 3.9+，仅标准库，不联网）：

```bash
python3 scripts/validate-role-library.py
```

如另有上述固定提交的本地上游checkout，可附加 `--upstream /path/to/agency-agents-zh` 检查来源文件哈希。脚本只读该目录，不执行其脚本。

行为验证使用 [评测说明](../evals/README.md) 的原场景与新增团队场景；结构检查不等于模型行为通过，更不等于真实平台发布已验收。更新上游时应重新读变化文件、评估适配、更新提交/哈希，并复查相关场景，不能直接覆盖本地角色卡。
